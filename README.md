I build software that answers one question well: **what is actually going on here?** Whether that's a 200-file codebase nobody understands, a coaching centre running on WhatsApp, or an export house tracking shipments in Excel — I turn the mess into a system with a clear boundary, a visible state, and an audit trail.

Based in **Chattogram, Bangladesh**. Full stack, TypeScript and Python, biased towards boring reliable architecture over novel complexity.

## What I'm building

### 🌳 [Arbor](https://github.com/mdadeel/Arbor) — architecture intelligence for GitHub repos
Connect a repository, get an inspectable map of its modules, its dependency graph and a prioritised health report, in about thirty seconds. Deterministic AST analysis — no configuration file, no CI setup, no workflow to install.

`Next.js 15` `tRPC` `Prisma` `PostgreSQL` `BullMQ` `React Flow` · **41k LOC · 259 tests**

→ [Live](https://arborgit.vercel.app) · [Code](https://github.com/mdadeel/Arbor)

### 🎓 [e-TuitionBD](https://github.com/mdadeel/etuitionhub-frontend) — marketplace + institution platform
A tuition marketplace for students and tutors, and underneath it a multi-tenant platform for coaching centres: branches, batches, attendance, exams, results, fees, guardians and staff roles.

`React 19` `Node.js` `MongoDB` `Socket.IO` `WebRTC` `bKash/Nagad` · **65k LOC · multi-tenant**

→ [Live](https://e-tuitionhub.vercel.app) · [Frontend](https://github.com/mdadeel/etuitionhub-frontend)

### 🚢 [Import Export Hub](https://github.com/mdadeel/iehub-server) — B2B trade operations
Verified organisations, RFQ-to-purchase-order workflows, document vaults, disputes, webhooks and audit logs — for export houses that currently run on email threads and spreadsheets.

`Express` `MongoDB` `RBAC` `Firebase` `React 19` · **org tenancy · audit trail**

→ [Live](https://iehub.vercel.app) · [Client](https://github.com/mdadeel/iehub-client) · [API](https://github.com/mdadeel/iehub-server)

### 🧹 [Preen](https://github.com/mdadeel/Preen) — Linux system maintenance, calmly
A GTK 3 desktop app for installing and removing apps, reclaiming disk space with an honest size preview, managing systemd services, and tuning swap and ZRAM. Every action can be simulated before it runs.

`Python` `GTK 3` `systemd` `Debian packaging` · **70 tests · MIT · v0.4.0**

→ [Code](https://github.com/mdadeel/Preen)

## How I work

- **Read the code before drawing the box.** Architecture decisions start from what exists, not from a whiteboard.
- **Make state visible.** If a system can't tell you what it's doing, that's the bug — in a codebase, a queue, or a payment ledger.
- **Test the boundaries.** Auth, permissions and money get tests first; the rest earns them.
- **Ship the boring parts.** Packaging, CI, releases and documentation are part of the product, not overhead.
